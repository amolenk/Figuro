# Excalidraw 0.18.1 SVG export: complex-scene facts

**Context:** [Research ticket #14](https://github.com/amolenk/Figuro/issues/14), part of [map #1](https://github.com/amolenk/Figuro/issues/1); follows [prototype ticket #13](https://github.com/amolenk/Figuro/issues/13).

**Scope:** Figuro pins `@excalidraw/excalidraw` to `0.18.1` ([package manifest](https://github.com/amolenk/Figuro/blob/main/packages/editor-host/package.json)). Findings below are from the matching Excalidraw tag’s implementation, declarations, and focused export tests. They record behavior and constraints; they do not set a Figuro support policy.

## Findings

- **Image resources:** `exportToSvg(elements, appState, files, opts?)` receives the binary-file map as its third argument. For an image to be drawn, its initialized `fileId` must resolve in `files`; the SVG renderer reads that file’s `dataURL` and emits an SVG `<image>` inside a reusable `<symbol>`, referenced by `<use>`. Reuse is on by default. Missing/unresolved file data takes the image branch without emitting an image node. The upstream transformed-image test supplies `file_A` in `files`, then asserts one embedded `<image>` and four `<use>` nodes for four image elements; its snapshot also records crop/clip and flip/rotation output. [Export implementation](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/scene/export.ts) · [SVG renderer](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/renderer/staticSvgScene.ts) · [image export test and snapshot](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/tests/export.test.tsx)

- **`scene.files`:** A scene’s `files` value is `BinaryFiles`, keyed by file ID; each `BinaryFileData` includes `id`, `mimeType`, and `dataURL`. Scene restore returns `data.files` or `{}`. Therefore image-bearing scenes need their file records passed to SVG export (the prototype’s `scene.files ?? {}` form is consistent with the API); the element’s `fileId` alone is not the image bytes. The renderer places the data URL into the SVG rather than resolving an external file URL. [File types and scene restore](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/types.ts) · [restore](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/restore.ts) · [SVG renderer](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/renderer/staticSvgScene.ts)

- **Bound text:** A text element with a `containerId` is skipped in the main render pass when its container is present in the render map. The container is rendered, then its bound text is rendered separately at the computed bound-text position. For arrows, the exported arrow group uses a mask to clear the label area. Thus bound text is not simply part of the container’s SVG geometry: it remains a distinct rendered text group, emitted at the container’s traversal point. [SVG renderer](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/renderer/staticSvgScene.ts) · [text/container relationships](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/types.ts)

- **Frames and clipping:** `frameRendering` controls frame outlines, names, and clipping; default app state enables all four frame settings (`enabled`, `clip`, `name`, `outline`). In a regular export, frame elements render as outlines only when enabled, names are added as temporary text elements, and a child with a resolvable `frameId` is wrapped in a `<g clip-path="url(#frame-id)">` when clipping is enabled. The clip path is defined from the frame bounds. An `exportingFrame` option instead selects overlapping elements, enables clipping, disables frame outline/name for that frame, removes export padding, and sizes the SVG to the frame. The upstream tests cover frame-child clipping/export, overlapping versus outside elements, and excluding elements assigned to a different frame. [export and frame preparation](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/scene/export.ts) · [frame utilities](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/frame.ts) · [default frame settings](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/appState.ts) · [frame export tests](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/tests/scene/export.test.ts)

- **Grouped content:** Elements have `groupIds`, but the SVG renderer draws scene elements individually and does not emit a wrapper or group identifier from those IDs. SVG grouping that appears in output is used for rendering concerns such as transforms, masks, and frame clips; it does not represent Excalidraw group membership. [element types](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/types.ts) · [SVG renderer](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/renderer/staticSvgScene.ts)

- **Figuro `customData`:** The element type permits arbitrary `customData`. The SVG renderer does not inspect it, so reveal-step and semantic-role metadata do not alter rendering or add SVG attributes. `exportEmbedScene` is false by default; when enabled, the original elements are serialized into SVG `<metadata>` before temporary frame-label elements are introduced. The JSON export cleanup retains nondeleted element objects (only clearing a linear element’s transient `lastCommittedPoint`), and restore preserves `customData`. Embedded scene metadata can therefore carry source custom data, but it is scene payload, not an association between a visual SVG node and its source element. [element types](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/types.ts) · [SVG export](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/scene/export.ts) · [JSON serialization](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/json.ts) · [element export cleanup](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/index.ts) · [restore](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/restore.ts)

- **Mapping visual SVG nodes back to elements:** The renderer adds `data-id` only when `isTestEnv()` is true; it is not a production-node identity contract. Output shape also prevents positional one-to-one mapping: an element can produce nested wrappers and auxiliary nodes (images use shared symbol definitions and `<use>` references; arrows with bound text add a mask; frame clipping adds wrappers), frame labels are synthesized, bound text is emitted alongside its container, and iframe-like elements are rendered in a later pass. Per-element render errors are caught and logged, so a failed element can also be absent. Consequently, mapping rendered nodes to source elements by child index is not reliable for these scenes, and production SVG does not consistently carry source IDs for role tagging.
