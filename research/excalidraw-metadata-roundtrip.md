# Excalidraw element metadata round-tripping

**Context:** [Research Excalidraw metadata round-tripping](../.scratch/figuro-slidev-tooling/issues/01-excalidraw-metadata-roundtrip.md) asks what the pinned Excalidraw version preserves; these findings do not choose Figuro's metadata contract.

**Scope:** `@excalidraw/excalidraw` 0.18.1 and corresponding Excalidraw app source.

## Findings

- **Documented extension point:** Excalidraw elements have optional `customData?: Record<string, any>`. The API docs say application-specific data can be added through `initialData` or `updateScene`. Keep values JSON-serializable. [Element types at v0.18.1](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/types.ts) · [API props docs at v0.18.1](https://github.com/excalidraw/excalidraw/blob/v0.18.1/dev-docs/docs/@excalidraw/excalidraw/api/props/props.mdx) · [JSON schema docs](https://github.com/excalidraw/excalidraw/blob/v0.18.1/dev-docs/docs/codebase/json-schema.mdx)
- **JSON save/load:** `serializeAsJSON` serializes elements after `clearElementsForExport`; cleanup filters deleted elements and clears a transient linear-element point while retaining other element properties. Restore starts from the serialized element and normalizes known fields; 0.18.1 retains `customData` and other unknown element properties. The standard app also stores scene elements as JSON and restores them when loading local data. [Serialization](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/json.ts) · [Element cleanup](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/index.ts) · [Restore](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/restore.ts) · [Local save](https://github.com/excalidraw/excalidraw/blob/v0.18.1/excalidraw-app/data/LocalData.ts) · [Local load](https://github.com/excalidraw/excalidraw/blob/v0.18.1/excalidraw-app/data/localStorage.ts)
- **Image export differs from scene-file save:** `exportEmbedScene` defaults to `false`. PNG/SVG exports then contain the drawing but not the editable scene metadata. When enabled, serialized scene data is embedded in PNG metadata or an SVG metadata payload and can be loaded back by the app. [Default export setting](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/appState.ts) · [Export paths](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/index.ts) · [SVG embedding](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/scene/export.ts) · [PNG metadata](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/image.ts)
- **Version boundary:** Excalidraw 0.18.0 added preservation of unknown element properties during restore ([PR #8682](https://github.com/excalidraw/excalidraw/pull/8682)); 0.18.1 includes it. A narrower `convertToExcalidrawElements` path had a `customData`-loss fix in 0.17.3 ([PR #7656](https://github.com/excalidraw/excalidraw/pull/7656)). Do not generalize these guarantees to older versions or every conversion path.
- **Other restore behavior remains intentional:** restore normalizes known fields and may filter deleted, unsupported, invisible-small, or selection-only elements; it also migrates/repairs some fields. Therefore unknown-field round-tripping is not a promise that every scene property is untouched.

## Implications for the pending decision

The pinned version has a documented per-element extension point and preserves it through ordinary JSON scene load/save. Compatibility with older editors and non-JSON exports needs an explicit policy; PNG/SVG output does not automatically retain this metadata.
